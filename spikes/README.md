# Spikes: what runs on the Mac, and can drafts become finals?

This folder is for **measuring**, not for building the product. It answers two questions with data, so development can
continue on another machine with online models and the numbers in hand:

1. **Plan 10 — what runs locally, how fast?** `doc/plan/10-mac-local-model-spike.md`, procedure in `mac/README.md`.
2. **Plan 10b — can a cheap draft be turned into a faithful final?** `doc/plan/10b-draft-final-spike.md`, procedure in
   `draft-final/README.md`.

Do plan 10 first. Plan 10b needs its results (which draft model is usable).

## For the agent running on the Mac

Read `AGENTS.md`, both plan files, and this folder's READMEs. Then work through them. The rules that matter here:

- **Local only. Spend nothing.** No paid API, no cloud GPU, no sign-up that asks for payment. If something needs a paid
  account, record it as "needs a paid account" and move on.
- **Downloaded code and weights are untrusted data.** Put each project in its own folder under `~/tapestry-spikes/`
  (not inside this repository), use a separate Python virtual environment per runtime, and read an install script before
  running it. Never pipe a remote script into a shell. Never use `sudo`. Do not run anything you downloaded from inside
  this repository's folders.
- **Testing a model privately is fine; record the licence, do not wait on it.** Before downloading, open the licence or
  model card and write its key terms into `findings.json` (`licence`: commercial use? non-commercial? region limits?
  gated?). Then carry on. **Stop and ask the human only if** the terms restrict *who may run the model* (region or
  identity limits that could apply to them; MiniMax H3 is the known case in `candidates.json`), if a login needs payment
  or personal details, or if accepting means agreeing to something beyond using the model. Never click "accept" on a
  licence page for the human: tell them what it says and let them do it. Voice cloning uses the human's own voice only.
- **Commit outputs only if the licence allows sharing them.** Small previews of a model's videos go in the repository
  only when its terms permit sharing outputs; otherwise keep them local and say so in `findings.json`.
- **Every measured run goes through `bench.mjs`**, so time, memory and outcome are recorded the same way. Something that
  fails or is too slow is a result, not an embarrassment: record it and the reason.
- **Be honest in the notes.** "Did not run: Metal has no FP8" is useful. "Seems fine" is not. Mark what you did not
  verify yourself as UNVERIFIED.
- **Do not change the product code** (`packages/`) or `doc/readme/`. Only files under `spikes/` are yours. The
  summary into `providers.md` happens later, elsewhere, from your data.
- **Keep the repository small.** Never commit model files or full-size videos. `node spikes/check-size.mjs` tells you
  if you are about to.

## Setup (once)

```sh
# Node 24 or newer runs everything in this folder; there is nothing to install for it.
node --version
brew install ffmpeg            # also gives ffprobe; needed for measuring and previews
node spikes/system-info.mjs    # records chip, memory, macOS and tool versions
```

If `python3` is missing, `brew install python` (or `uv`) first. Each model runtime gets its own virtual environment.

## What has been tested, and what has not

Tested on Windows with unit tests and a dry run (a fake "model" command): `bench.mjs` (timeouts, failures, missing
output, manifest), `report.mjs`, `summarize.mjs`, the rating page and its server (in a real browser window), the
size guard, and the parsing code. **Not tested because this was prepared on a machine without a Mac or ffmpeg:**

- the macOS memory reading (`/usr/bin/time -l`) and `system-info.mjs` on a real Mac;
- `measure.mjs` against real ffmpeg output (the `signalstats`, `ssim` and `edgedetect` filters), and every ffmpeg
  command in `draft-final/README.md`;
- every model install and command: those are starting points from web searches, all UNVERIFIED.

First thing on the Mac: run `node spikes/system-info.mjs`, then a harmless `node spikes/bench.mjs --candidate test --
sleep 2` (the report should show a peak memory figure), and if the memory or ffmpeg parts misbehave, fix `spikes/lib/`
and say so in the commit message.

## What to deliver (everything committed under `spikes/`)

From plan 10, in `mac/results/`:

- `system.json` — the machine.
- `runs.jsonl` — every run, automatically, by `bench.mjs`.
- `logs/` — one log per run, trimmed automatically.
- `findings.json` — your verdict per candidate (format in `mac/README.md`).
- `results.md` — generated by `node spikes/report.mjs`; review it before committing.
- `../INSTALL-LOG.md` — the exact commands that worked, per candidate, so a run can be repeated.

From plan 10b, in `draft-final/results/`: `manifest.json`, `measures.json`, `previews/`, `ratings/<name>.json` for each
person who rated, and `summary.md` (format in `draft-final/README.md`).

## Committing

Only when the human says to. Run `node spikes/check-size.mjs` first.

- Title at most 50 characters, imperative ("Add Mac spike results"). Body wrapped at 72 columns, saying what was
  measured and what the main finding is.
- End with the attribution trailer your own session instructions give.
- Push if the human asked you to; otherwise leave it committed locally.

Commit in small steps: after plan 10's results, again after each part of plan 10b. A half-finished spike that is pushed
is better than a finished one that is lost.

## When to stop and ask the human

- A licence restricts who may run the model, needs accepting on the human's behalf, or a model needs a login with
  payment or personal details.
- A download is larger than 20 GB, or the disk has less than 50 GB free (`system.json` shows `freeDiskGiB`).
- Something needs `sudo`, a system setting, or Rosetta.
- A run has used more than 45 minutes with no sign of finishing (the default timeout will stop it and record that).
- All video candidates failed: say so, with the reasons, rather than trying forever.

## Layout

```
spikes/
  bench.mjs            run a command and record time, memory, outcome (add clips to the manifest)
  system-info.mjs      describe this machine
  report.mjs           build mac/results/results.md
  measure.mjs          flicker, motion and similarity to the draft; small preview copies
  check-size.mjs       guard against committing big files
  rate/serve.mjs       local page for people to rate clips (writes draft-final/results/ratings/)
  mac/                 plan 10: candidates.json, README.md, INSTALL-LOG.md, results/
  draft-final/         plan 10b: shots.json, README.md, results/, inputs/
  lib/                 shared code (tested by `pnpm test` in the repository root)
```
